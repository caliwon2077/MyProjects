# 开源项目审查与 Demo 验证

用户指定项目或父目录后，确认目标目录，读取适用 AGENTS.md、清单、锁文件与启动文档，识别已有改动。以本地快照为审查对象；记录日期、版本、Git 提交（可取得时）、操作系统和架构。ZIP 无 Git 元数据时明确说明，必要时记录关键源码 SHA-256，不推断其等于远端最新版本。

## 审查与执行

- 分辨产品类别。没有大模型自主决策/工具调用循环的程序，不因为存在自动化、机器人、agent 文件或强化学习示例就写成 LLM Agent。
- 沿实际入口追踪输入、核心处理、输出及外部依赖。Agent 项目写明模型/驱动、上下文、任务分工、工具调用、审批、停止与失败处理，并给出源码定位。
- 审阅与本次用途相关的正确性、认证与权限、凭据存储、外部调用、许可证边界、依赖和可维护性。结论分为已复现缺陷、源码支持的风险、推断与未验证项，不把代码注释或 README 宣传当成实测。
- 优先按锁文件使用指定工具链，在项目虚拟环境、独立构建目录和临时数据目录安装、构建和测试。不得为图省事升级所有依赖或覆盖用户已有配置。
- 尽量跑通一个具有可观察结果的 demo；仅启动进程、出现帮助或 HTTP 200 不等于核心流程通过。记录命令、退出码、结果断言、关键日志及启动/停止方法，材料放入 `audit/`。修复明确阻塞并做针对性回归。
- 模拟引擎与真实模型调用、官方发布包与本地源码、无界面核心与完整 GUI、单站点与全量覆盖分别验收。缺凭据时优先隔离 fake/mock，并明确真实链路未验证。不得自动使用个人凭据发消息、购买资源或部署公网。
- 网络失败先区分沙箱限制、代理、版本与上游故障；可读取已有代理并仅对本次命令使用。外部写入结果不明先核对再重试；没有新证据不反复安装。依赖未完成不得开始依赖它的构建。
- 测试与风险相称；禁止把“没有发现”写成“没有漏洞”。尽量只启动有限工作进程，清理自己启动的精确进程。保留有用的 demo 和证据。
- 需要界面操作时按当前会话的浏览器与 ComputerUse 委派规则执行；没有该规则或能力时不强加固定工具或模型。

## 每个项目交付两份报告

在项目根目录写 `审查报告_专业版.md` 与 `审查报告_小白版.md`。两版结论一致，小白版用日常比喻解释术语，保留重要限制、费用与启动步骤。

两版均覆盖：

1. 项目简介、适合/不适合用户和具体用途。
2. Agent 环节及每个环节具体工作；无 Agent 时明确写无，并说明作为 Agent 工具或环境的可能性属于接入方案。
3. 有源码或实测支持的亮点及代价。
4. 第三方调用能力：CLI、API、SDK、MCP、Webhook、库绑定等真实入口；区分现成接口与需自行封装，判断独立使用或组件嵌入及许可证边界。
5. 本机资源、源码/依赖/构建磁盘占用、实测峰值内存与耗时（注明场景与口径）、官方要求、工程建议、云服务/模型费用；没有测量的值不写成实测。
6. 审查发现的严重度、证据、影响、修复/规避方式和剩余问题。
7. demo 验收矩阵与复现步骤；失败说明具体阶段、错误、尝试、恢复条件。
8. 修改清单、验证范围与证据链接。
9. 审查和启动调试的 token 统计，按下述口径。

## Token 诚实计量

优先使用会话或平台实际提供的 usage，注明输入、输出、缓存、推理、总量的可见字段及统计时间。只有项目/阶段边界的 usage 可用时才分摊；共享上下文不能任意按比例分配。不得读取无关历史聊天或凭据以凑统计。

区分“助手分析和调试的模型 token”“被测项目调用模型的 token”“Shell/编译耗时”。终端命令本身没有模型 token，但发命令、读取日志和分析结果会消耗助手 token。没有 usage 时填写“无法取得实际值”，说明当前工具未暴露统计，不能写成 0。可另列有方法、文本范围和 tokenizer 名称的可复算估算，但它不等于实际消耗，不能覆盖不可见推理与重复上下文。

## 最终验收

核对每个目标目录两份报告均已生成、链接和命令有效、两版一致、所有“通过”均有证据，失败没有被替代路线掩盖。简短交付文件链接、各项目实际跑通层级、阻塞与恢复条件。若用户另外要求制作技能，以本技能作为流程参考，遵循当前 skill-creator 规则处理安装和验证。
